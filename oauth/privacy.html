Google user data disclosure

Privacy policy

This policy describes the handling of Google account data by TMNM Meta Publisher, an owner-operated editorial application under Truth Matters News Media.

Last updated: 22 October 2026

Verification status. The Google OAuth application has been switched to In production, but its brand and sensitive/restricted scope verification are not complete. The original code and current setup are under review; this notice does not imply independent security certification or Google's approval. The app is not being offered for unrestricted external onboarding while those checks remain unresolved.

1. Operator and contact

Application: TMNM Meta Publisher. Editorial identity: Truth Matters News Media (TMNM), an owner-operated project. Privacy enquiries, access questions and requests concerning data held in the application can be directed to awhistler@gmail.com. The final legal/trading entity designation has not yet been confirmed for broader external operation.

2. Google user data requested

Inspected desktop source requests Google Drive access (potentially including file contents, metadata, creation, edits and file-management operations); Google Docs access (reading and editing document contents); Google Apps Script project and deployment read access; and Apps Script external-request permission. A broad Drive grant may allow the app to access more than one manually chosen file. The exact current Cloud scope declarations, deployed Apps Script manifest permissions and active grant status still require reconciliation. The inspected client does not request a YouTube scope; any YouTube connection uses a distinct authorisation path.

3. Why data is used

Google data is intended to support the account holder's editorial document retrieval, editing, organisation, status inspection and specifically authorised workflow actions. Google user data is not to be sold, used for third-party advertising, data-broker resale, unrelated profiling or credit scoring. Any use for a materially different purpose requires a revised disclosure and consent where appropriate. Use of Google API data is subject to Google's API Services User Data Policy and its Limited Use rules.

4. Where data may be stored and how long

Source documents may remain in the account holder's Google Drive. The local operator system can keep workflow copies, diagnostic information and audit/evidence records on its Windows host, and related authorised operations may leave Google-hosted or Apps Script artefacts. The source review identified protected local credential handling, but it does not establish a complete independent assessment of deployed security or data flows. There is no verified universal automatic deletion deadline for every category of record: operational and audit records may be retained while relevant for workflow integrity, legal obligations, safety or restoration. An operator-reviewed request can identify records for deletion where technically and legally possible. Backups, Google-held files or independently processed copies may require separate handling.

5. Sharing and outside services

Information may be exchanged with Google Drive, Docs and Apps Script to carry out authorised operations. Other editorial or publishing tools, including third-party AI processing, may be used only where separately activated and appropriately disclosed. The inspected desktop source alone does not establish which external services currently receive Google user data. The operator must verify recipients, data categories, consent and retention controls before enabling any separate transfers. Google user data is not to be sold or transferred for advertising or unrelated commercial use.

6. Revocation, access and deletion requests

Authorised Google connections can be reviewed and revoked via Google Account third-party connections. Revoking access does not itself delete files or past copies. To request information about an account's stored application data or deletion of operator-controlled copies, email awhistler@gmail.com. Describe the relevant account or document without including passwords or access tokens. Requests will be reviewed for identifiable material, technical feasibility and applicable audit, recovery or legal obligations; we do not promise immediate or total deletion from unrelated systems.

7. Security, changes and limits

This GitHub Pages website is informational and does not request Google passwords or obtain OAuth tokens. App credentials and local source infrastructure are distinct from this public site. The operator intends to limit access to authorised workflows, but actual current authorisation boundaries and all deployed processors have not been independently confirmed. Any change in the use of Google account data must be reflected in an updated policy and, where needed, a new consent request. This document does not authorise public publishing or waive platform approval requirements.
